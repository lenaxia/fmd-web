### Known behavioral divergences (v0, documented)

1. **CSS selector engine** — `css()` runs linkedom’s css-select (CSS3); InternetTools’ css3 subset differences (e.g. `:has`) degrade to swallowed-empty per FMD2 semantics.
2. **JSON node tree** — objects → key-named child elements, arrays → `item` child elements, typed scalar leaves (string/number/boolean/null markers); `name()` member steps rewrite to `/*` (chained `name()()` to nested member steps), `?key` to `/key`; `not(` rewrites to `fmd:not(` carrying InternetTools’ JSONiq EBV (false/0/""/null → false). KNOWN GAP: a BARE `[prop]` predicate over a JSON tree keeps standard node EBV (always true) instead of the boxed-value EBV — FMD2 modules express the filter as `not(prop)`; unexercised by the seed corpus.
3. **EHentai.lua:71 `.x` field** — reads a nonexistent TXQuery field (`CreateTXQuery(...).x`); FMD2 errors identically (LuaClass `__index` unknown key → nil). The host records the failed dispatch; the update thread keeps the default page count (uUpdateThread.pas:198).
4. **Parser preprocessing (corpus-proven divergences only)** — CRLF/CR → LF in text and attributes (parseTextAttribute/parseCDATA normalization); adjacent text nodes merged (readText append semantics — character references never split runs); comments/PIs dropped (readComments/readPIs = false); whitespace text after `</body>` skipped (bpmAfterBody); bare text payloads scaffolded into html/head/body (repairing parser); XQuery string literals normalize CR → LF (LineEndingNormalization xqlenXML1). Implicit node→string coercion inside OTHER XPath functions (substring/upper-case over elements) uses fontoxpath’s raw string value — the seed corpus proves no divergence there.
5. **TASK.CurrentDownloadChapterPtr / TASK.CurrentMaxFileNameLength = 0 — the one-chapter-per-job EQUIVALENCE (audit N-2)** — fmd-web runs one chapter per download job where FMD2 walks a chapter list, so the host returns the constants 0. Readers get IDENTICAL links: FMD2’s Pascal `Strings[i]` is 0-based (LuaStrings.pas:88), so `TASK.ChapterLinks[TASK.CurrentDownloadChapterPtr]` resolves slot 0 — the same link fmd-web’s seeded TASK carries; EHentai.lua:156’s length limit check is correctly INERT with 0 = no limit, and the host-side D5 truncation owns the filename length limit (read by ~10 modules + 2 templates: MangaFire.lua:324, DataLife.lua:112, …).

## fmd.crypto compatibility notes (LuaCrypto.pas → `crypto-core.ts`/`crypto-shim.ts`)

**Backends.** `node:crypto` (MD5/SHA*/HMAC, PBKDF2, AES CBC/CFB/CTR/OFB/ECB/GCM,
CFB8, ECDH P-256), `sodium-native` (X25519 `crypto_scalarmult(_base)`,
SecretStream pull), pure JS (RC4 — see the OpenSSL note below, MD4 — OpenSSL 3
dropped it, the synacode encoders/CRCs, DCP's exact CBC/CFB variants, the
base64 Lua↔JS bridge). Full details and vectors: `docs/evidence-dual-sapling-picnics.md`.

**RC4 (OpenSSL legacy provider note).** FMD2's `RC4` is DCPCrypt's pure-Pascal
`TDCP_rc4` (BaseCrypto.pas:470–489, textbook KSA + PRGA, no drop-N) — it never
touches OpenSSL. The JS implementation is likewise pure JS (the same textbook
KSA + PRGA over the same guard rules: `''` when data/key empty or key > 256
bytes), so **the JS impl does not differ** — and deliberately does not
delegate to `node:crypto`, where RC4 sits behind OpenSSL 3's legacy provider
(unavailable by default in the docker target). Verified against classic RC4
test vectors and the roundtrip properties in `crypto-vectors.test.ts`.
(For completeness: the Pascal functions that DO load OpenSSL are the X25519/
P256 ECDH set via `libcrypto.so.3` direct linkage — those need no legacy
provider; the JS side maps them to sodium-native/node ECDH below.)

**MD4 note.** OpenSSL 3 dropped MD4 from the default provider (and FMD2 gets
it from synacode's own Pascal port anyway), so `MD4`/`MD5LongHash`'s core is
a pure-JS RFC 1320 implementation — all 7 published RFC 1320 test vectors
pass (`crypto-vectors.test.ts`).

**sodium-native (docker target).** `sodium-native` ships prebuilt libsodium
binaries for linux-x64 (no OS packages needed); `docker/Dockerfile` runs a
build-time smoke check — `require('sodium-native')` + a `crypto_scalarmult`
probe — so an image whose native backend cannot load **fails the build**.
Tests guard on `sodiumAvailable()` and skip with an explicit reason string
when the native build is unavailable in a dev runtime; in that case X25519/
SecretStream degrade to exactly the Pascal OpenSSL-failure paths
(`''` / nil / zero returns — `loadSodium()` returning null mirrors the Pascal
`EVP_*` returning nil). P256 uses node ECDH (`crypto.createECDH('prime256v1')`
+ the Pascal's exact SEC1/SPKI DER wrappers) and therefore does NOT depend on
sodium: libsodium has no P-256.

**Byte-exact Lua bridge.** wasmoon marshals Lua strings as UTF-8 (replacement
chars on read, NUL truncation, UTF-8 encode on push) which would corrupt the
crypto API's byte-string arguments. The shim installs a pure-Lua base64
codec; every Lua argument is base64-encoded Lua-side, JS decodes → core →
base64-encodes results, Lua decodes back. Byte-exact for NUL and 0x80–0xFF,
one uniform protocol; the result protocol mirrors the Pascal `lua_push*`
returns exactly (string / integer for CRC16/CRC32/tags / nil via sentinel
for InitPull failure / **zero returns** for P256_GenerateKeyPair and
SecretStream_Pull failure — Pascal `Result := 0` / multi-returns).

The `pb` shim uses the same bridge protocol for descriptor/message wire
bytes (`pb-shim.ts` `PB_LUA_GLUE`): `pb.load`/`pb.decode` args and
`pb.encode` results are base64-enveloped Lua-side; `pb.load`'s
two-value `(ret, pos)` return crosses as a real Lua multi-return
(`pb-protoc.integration.test.ts`).

**SecretStream state token (documented deviation).** The Pascal carries the
64-byte raw `TSecretStreamState` (k 32 + nonce 12 + pad 20) through Lua as a
binary string; the JS shim
carries the libsodium state as an **opaque base64 token** (raw binary state
cannot round-trip wasmoon losslessly). Both are opaque to the caller — same
Init/Pull wire contract, same header/tag semantics, rekey handled
internally. Cross-checked against libsodium push streams (multi-chunk,
empty messages, TAG_FINAL, tamper → zero returns) in
`crypto-bridge.test.ts`.

**DCP cipher semantics carried over** (the reason several AES variants are
implemented directly rather than delegated):
- Key classes: DCPrijndael zero-pads keys < 16/24/32 bytes into the next
  class; > 32 bytes raises in Pascal → `''`.
- Nil-IV default: DCP initializes the chaining value with **E_K(zero block)**
  when `Init` gets no IV — this is what `EncryptString` uses.
- CBC: DCP processes a partial tail block with an E(CV) keystream rule and
  the composed variants pad explicitly; ECB+PKCS7 uses manual pad (always
  appends 1..16) and a **blind pad chop** on decrypt (`Pkcs7RemovePad` never
  validates — mirrored).
- CTR: full 16-byte big-endian counter wrap (Pascal byte-wise carry loop).
- GCM: ciphertext ‖ 16-byte tag, arbitrary IV lengths via the GHASH J0 path
  (12-byte IVs take the J0=IV‖0⁷‖1 fast path) — cross-checked byte-for-byte
  against OpenSSL GCM incl. AAD and tag/AAD tamper → `''`.
- `EncryptString`/`DecryptString` (uBaseUnit.pas:1556–1589): AES-256 key =
  `SHA512('B74945FB50E84FD58BF9FEAB8E4BEA6B')[0..32]` (DCP InitStr with
  TDCP_sha512 → min(512, 256) bits), IV = E_K(0¹⁶), DCP blockcipher
  EncryptString = **CFB8** + standard base64 (canonical DCPcrypt2 2.0.4) —
  verified by independent openssl `aes-256-cfb8` composition
  (`crypto-composed.test.ts`).

**Lenient edges (Pascal parity, all vector-tested).** `HexToStr` → `''` on
odd length or any non-hex char; DCP Base64 decode is garbage-in/garbage-out
(invalid chars skipped, no error — DecryptString of non-base64 does NOT
yield `''`); `AESDecryptCBCMD5Base64ZerosPadding` uses the **32-char MD5 hex
TEXT** as the AES-256 key (BaseCrypto.pas:362 — not hex-decoded);
`MD5LongHash('' , 0)` divides by zero in the Pascal → surfaces as a Lua
error (asserted via `pcall` returning false); URL encode/decode replicate
synacode's exact char sets and DecodeTriplet quirks; HTMLDecode replicates
uBaseUnit's entity set, `else Exit` truncation and Chr>255 truncation.

**Coverage map.** `crypto-vectors.test.ts` — known-answer vectors (RFC 1320
MD4 ×7, RFC 1321, RFC 2202, RFC 4231, RFC 7914, CRC32/16, LongHash, RC4,
encodings incl. Pascal-quirk vectors). `crypto-ciphers.test.ts` —
encrypt/decrypt roundtrip properties for every cipher pair (ECB/CBC/CFB/
CTR/OFB/GCM ± AAD over key classes × length grid, SP800-38A blocks,
OpenSSL/aes-js cross-checks), RFC 7748 X25519, P256 ECDH interop,
libsodium push → pull SecretStream flow (criterion 2). `crypto-composed.test.ts`
— composed FMD2 variants against hand-derived vectors with per-vector
derivation notes citing the Pascal lines (criterion 3). `crypto-bridge.test.ts`
— wasmoon integration: full surface require-able, byte-exact binary
roundtrips, result/arity protocol, module-shaped flows. Surface completeness

`contract/contract.json` `requireShims` entry carries the implementation note.

## HTTP shim compatibility notes (httpsendthread.pas → `engine/shims/http-*`)

The full §5.4 surface lives in `http-shim.ts` (facade) over `http-pipeline.ts`
(the `DefaultHTTPRequest` port: URL massaging, retry loop, redirect loop,
response-state per hop, decompression, success ⇔ `Document.Size > 0`),
`http-url.ts` (synacode `EncodeURL`/`DecodeURL` + `SplitURL`/
`MaybeEncodeURL` ports), `http-headers.ts` (`Reset`/`ResetBasic`/`AcceptImage`
default sets), `http-cookies.ts` (jar + the §5.3 `SharedCookieJar` port),
`http-proxy.ts` (`SetProxy` :838-874 parity: HTTP → undici `ProxyAgent`,
SOCKS4/5 → socks-proxy-agent-backed dispatcher), `http-egress.ts` (SSRF hook:
RFC1918/link-local denied by default, allow-list override), `http-hostgate.ts`
(per-host connection limits + start-interval delays) and `http-transport.ts`
(sync one-hop port: recorded fixtures, or a loopback-only worker-thread pump
for the local mock-server integration tests).

**Documented divergences (each carries its reason):**
- **The wire boundary refuses CR/LF in header names/values (audit F-1)** — cookie/header
  STORAGE keeps values verbatim (FMD2 TStrings-jar parity — the jar may hold anything),
  but a CR/LF reaching the request line would split it (header-injection class; node:http
  rejects it mid-write). FMD2's synapse would equally fail the socket write and lose the
  request; fmd-web fails fast instead: the ONE request is refused with a typed
  `… contains CR/LF — refused at the wire boundary` error (transport + pipeline boundaries),
  the shared transport worker survives, and a poisoned request can never wedge the process
  (the pump's perform() is fault-wrapped; a dead worker is recreated on the next send).
- **Accept-Encoding omits zstd** (D13) — the Pascal `ResetBasic` advertises
  `gzip, deflate, br, zstd`; the shim advertises `gzip, deflate, br` unless a
  zstd decoder is enabled. Decompression still honors a zstd response header
  when node's zlib provides it.
- **`ResetBasic` keeps the cookie jar** — FMD2 clears the per-request cookie
  working set that its `CookieManager` re-seeds each hop; the shim's jar IS
  the §5.3 shared state, so clearing it would break cross-request
  persistence (`ClearCookies`/`ClearCookiesStorage` remain the explicit wipes).
- **URL percent-encoding is UTF-8-byte oriented** — the Pascal `AnsiString`
  encodes each ANSI byte #127..#255; the shim encodes the same special set
  over UTF-8 bytes (round-trips through `DecodeURL`).
- **Retry/redirect counters are per-request** — the Pascal `counter`/
  `redirectcounter` are unit-level globals (shared across threads); the shim
  makes them per-request (deterministic, same bounds).
- **`SplitURL` quirks preserved**: dot-less hosts with ports degenerate
  (port appended after the fallback host), relative redirect Locations lose
  directory context, scheme defaults to `https://`.
- **Egress policy** (new, §5.4 hook): private/link-local targets are denied
  before any socket; hostname/IP-literal checking only (no DNS-resolution
  rebinding defense — documented boundary).
- **Document `LoadFromFile`/`SaveToFile` are jailed** to the configured fs
  root (no jail configured ⇒ both are no-ops); FMD2 raises on I/O errors,
  the shim degrades to `false`.
- **Loopback transport is http-only** — the local mock-server transport
  refuses non-loopback hosts and https (the §13 zero-network guarantee);
  recorded fixtures cover https URLs offline.
- **Hop-by-hop response headers are stripped when re-sent** — the FMD2
  header-bleed quirk (response Headers become the next request's headers) is
  preserved at the facade level, but `connection`/`transfer-encoding`/
  `content-length`/`host` etc. are sanitized by the loopback transport
  (node:http request validation rejects `Transfer-Encoding` + `Content-Length`).

## fmd.gzip compatibility notes (LuaGZip.pas + GZIPUtils.pas → `gzip-shim.ts`)

**Format detection (unzipStream parity).** gzip magic (`1f 8b 08`), zlib
(CMF low-nibble 8 + CMF/FLG checksum — RFC 1950), else raw deflate. The
Pascal's zlib test is a loose `hdr and $78 = $78` byte mask
(GZIPUtils.pas:196); the facade uses the RFC-strict CMF/FLG check —
identical outcomes for every real-world stream (deflate emits CMF=0x78);
synthetic CMF≠0x78 streams route differently but fail loud→nil on both
sides. gzip: CRC32 + ISIZE verified (GZIPUtils.pas:244-246) — node
`gunzipSync` performs the identical checks. zlib: Adler-32 verified
(:247-252). Raw: no trailer on either side.

**Failure parity.** `unzipStream` false → the Pascal logs
`GZip.Inflate() unzipStream failed` (MultiLog SendError) and returns no
values (nil); the shim logs the same line through the module-correlated
host logger (level error) and yields nil. Never a Lua error. Truncated,
corrupted-trailer, garbage and empty inputs all take this path.

**Binary fidelity (base64 bridge).** Happymh.lua feeds raw compressed
bytes (`plain:sub(5)` after the `SC01` magic); wasmoon text marshalling
corrupts NUL/high bytes, so Inflate's argument and result cross over the
same pure-Lua base64 codec as fmd.crypto (idempotent-guarded globals
`__fmd_b64enc`/`__fmd_b64dec` installed by the gzip glue). Byte-exact
for NUL and 0x80–0xFF (0-255 roundtrip asserted).

**Documented edges.** Multi-member gzip: the Pascal verifies the first
member against the LAST 8 trailer bytes (fails → nil); node concatenates
members and succeeds — divergence, no real-world consumers. FDICT zlib
streams fail on both sides (the Pascal skips the 6-byte header without a
dictionary; node throws) → nil. Detection-rule edge above (CMF≠0x78).

## fmd.pcre2 compatibility notes (LuaPCRE2.pas → `pcre2-shim.ts`)

**Backend (offline target).** RE2-native and pcre2-wasm are not
vendorable in this repo (no registry access, zero-network CI), so the
facade compiles to the host V8 RegExp engine. PCRE2_UTF without
PCRE2_UCP keeps `\w \d \s` ASCII — JS keeps them ASCII in BOTH modes,
so the no-`u` compile is faithful; `u` is enabled only for patterns
needing it (named groups, `\p{...}`, `\k<name>`, `\x{...}`/`\o{...}`),
where JS `\w \d \s` stay ASCII too (verified). Cost context (D11):
fmd.pcre2 has 0/418 tree-module consumers and 0 seed consumers today —
every gap below is documentation-only until a real consumer lands.

**Translation layer (exact, vector-tested).** `\A`→`^`, `\z`→`$`,
`\Z`→`(?=\n?$)`, default `$`→`(?=\n?$)` (PCRE2 matches before a final
newline — no DOLLAR_ENDONLY), `\h/\H/\v/\V` → the exact HSPACE/VSPACE
sets, `\N`→`.`, `\R`→`(?:\r\n|[...])`, `\a`/`\e`/`\cX` → control codes,
`\x{hex}`→`\u{hex}`, `\o{oct}`→`\u{dec}`, `\Q..\E` quoting (class-safe;
`-` escaped only inside classes), `(?P<name>`/`(?P=name)` aliases,
`\g{n}`/`\g{name}` backrefs, `(?#...)` comments stripped, `(*LF)`/
`(*UTF)`/`(*UTF8)` stripped (facade defaults: LF newline, always UTF),
top-level `(?ims)` hoisted to compile flags (the applies-from-here
semantics degrade to whole-pattern).

**Downgrades (behavior divergence, vector-pinned).** Possessive
quantifiers `*+ ++ ?+ {n,m}+` → greedy (backtracking allowed — the
`".*+"` on `'"" x ""'` vector pins the divergence); atomic groups
`(?>…)` → non-capturing.

**Loud-fail ledger (each takes the Pascal compile-failure path: log +
false/no-values/subject-unchanged — never a silent stub).** `\K`
(match-start reset), `\C`, `\X` (grapheme cluster), `\G`, recursion
`(?R)`/`(?n)` and subroutine calls `(?&name)`/`(?P>name)`/`(?1)`-style
references, conditionals `(?(cond)...)`, callouts `(?C...)`, branch
reset `(?|...)`, inline `(?x)`/`(?U)`/`(?u)`/`(?J)`/`(?n)`/`(?X)`,
inline-flag negation `(?-i...)`, scoped inline flags `(?flags:...)`,
`(*verbs)` beyond LF/UTF/UTF8 (ACCEPT/FAIL/MARK/PRUNE/SKIP/THEN/COMMIT/
CR/CRLF/ANYCRLF/ANY/NUL/BSR_*), `\R` inside a character class.

**Substitution-string edges.** PCRE2 `$n`/`$0`/`$$`/`${name}` expanded
over matches; an out-of-range group number and an unknown `${name}`
stay literal text (PCRE2 errors — the facade keeps the string; lean
deviation). JS `$\`` / `$'` are NOT special (PCRE2 parity).

**Semantic divergences (documented).** `^` never matches at a non-zero
startoffset (PCRE2 treats startoffset as a virtual string start without
NOTBOL; vector-pinned false). Lookbehind still sees characters before
the start offset (PCRE2 parity). Unset capture groups return ''
(the PCRE2_UNSET Cardinal wrap in the ovector helpers,
pcre2.pas:290-298 — parity). `gsub` copies the whole subject out with
substitutions from the start offset (pcre2_substitute parity); after an
empty match the skipped character is copied and the position advances
by one (pcre2_substitute parity). gmatch (re_gmatch's ExecNext
iterator, LuaPCRE2.pas:165-195) continues at the match end and loops
forever on non-advancing zero-width patterns (FMD2-identical).
Byte-level subjects are a non-goal: PCRE2_UTF requires valid UTF-8
anyway (invalid UTF-8 → PCRE2 match error); wasmoon's replacement-char
normalization on invalid sequences is the documented text-mode
deviation.

## fmd.logger compatibility notes (LuaLogger.pas → `logger-shim.ts`)

The complete LuaLogger API (LuaLogger.pas:33-45): `Send`/`SendWarning`/
`SendError` — routed to the structured host logger with module-id
correlation (§4). MultiLog level parity: Send→log, SendWarning→warn,
SendError→error. `luaToString` coercion (LuaUtils.pas:206-213 =
lua_tolstring): strings and numbers coerce, every other type (nil,
booleans, tables) → '' — never a Lua error. The Pascal `Logger.Send`'s
MultiLog level is the info level → HostLogRecord `log`.
